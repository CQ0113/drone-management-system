# 🛸 Project Overlord: Drone Swarm Management

### *Laravel-powered Search & Rescue Command Center*

[](https://laravel.com)
[](https://threejs.org)
[](https://ollama.com)

**Project Overlord** is a 3D swarm simulation designed for high-stakes search-and-rescue (SAR) operations. Using a Laravel backbone, a Three.js sandbox, and local LLM "brains" via Ollama, it transforms raw data into coordinated aerial intelligence.

-----

## ⚡ Core Intelligence

  * **🕹️ The Sandbox:** A real-time 3D environment at `/swarm-sandbox` to visualize drone telemetry, obstacle fields, and survivor pings.
  * **🧠 Neural Planning:** Powered by **Ollama**. Each drone receives mission-critical objectives (`scan_sector`, `move_to`, `return_to_base`) generated by local AI.
  * **🔋 Physics-Aware:** Simulation tracks battery depletion, signal range, and discovery logic.
  * **📡 Single Source of Truth:** A dedicated CLI runner (`swarm:run-ai`) ensures the simulation state remains consistent, even when the frontend is thirsty for updates.

## 🚀 Deployment Briefing

### 1\. Secure the Perimeter (Installation)

```bash
git clone <your-repo-url> && cd drone-management-system
composer install
cp .env.example .env
php artisan key:generate
```

### 2\. Prepare the Data Grid

```bash
# Initialize the SQLite database
mkdir -p database && touch database/database.sqlite
php artisan migrate
```

### 3\. Prime the Visuals & AI

```bash
npm install && npm run build
# Pull the lightweight 'brain'
ollama pull qwen2.5:0.5b
ollama serve
```

## 🕹️ Mission Control

To launch the operation, you need **two active channels** (terminals):

**Terminal A: The Uplink** (Web Server)

```bash
php artisan serve
```

**Terminal B: The Hive Mind** (Simulation Runner)

```bash
# This executes the AI logic and pushes the state to the cache
php artisan swarm:run-ai --init-if-missing
```

**🌐 Access Point:** [http://127.0.0.1:8000/swarm-sandbox](http://127.0.0.1:8000/swarm-sandbox)

## 📡 Tactical API & Commands

### Quick-Start a Mission

Force-initialize the swarm with a pre-defined sector:

```powershell
Invoke-RestMethod -Uri "http://localhost:8000/api/init-swarm" -Method Post -Body '{"use_default_map":"map1"}'
```

### Survivor Watch

Monitor found survivors in real-time from your terminal:

```powershell
while ($true) { 
    php artisan tinker --execute="echo now()->format('H:i:s').' | Survivors: '.json_encode(Cache::get('swarm:found_survivors', []))"
    Start-Sleep -Seconds 1 
}
```

## ⚠️ Troubleshooting the Uplink

  * **500 Error on UI:** The drones are blind\! Run `php artisan config:clear` and check your `APP_KEY`.
  * **Stale Data:** If the drones aren't moving, ensure **Ollama** is responding. A simple `ollama list` in your terminal will verify the service is alive.
  * **Laggy Ticks:** Check `LLM_PROVIDER` in `.env`. Using a model too large (e.g., 70B) on a laptop will lead to 1-minute "seconds."

## 📊 Benchmark Harness

This repo now includes a two-part benchmark harness under [benchmarks/k6/swarm-api-benchmark.js](benchmarks/k6/swarm-api-benchmark.js) and [benchmarks/scripts/mission-kpi-benchmark.mjs](benchmarks/scripts/mission-kpi-benchmark.mjs).

### 1) API Load and Latency (k6)

Benchmark tick endpoint latency, failure rate, and planner timing under concurrent load.

```bash
# Prerequisite: install k6 (https://k6.io/docs/get-started/installation/)
npm run bench:api
```

Optional tuning with env vars:

```bash
BASE_URL=http://127.0.0.1:8000 MAP_ID=map2 VUS=10 DURATION=60s FORCE_REPLAN_EVERY=6 npm run bench:api
```

### 2) Mission KPI Benchmark (Node)

Runs sequential ticks and writes a KPI report JSON (coverage, survivor discovery, danger proximity, battery efficiency, latency percentiles).

```bash
npm run bench:mission
```

Optional tuning:

```bash
node benchmarks/scripts/mission-kpi-benchmark.mjs --baseUrl http://127.0.0.1:8000 --map map3 --ticks 180 --forceReplanEvery 6 --dangerRadius 2
```

Output is written to `benchmarks/output/mission-kpi-<timestamp>.json`.

### 3) Run Both

```bash
npm run bench:all
```

### Suggested Targets

  * Tick HTTP `p95 < 500ms`
  * Tick error rate `< 1%`
  * Stable coverage/minute across repeated runs
  * Low danger proximity events over time
